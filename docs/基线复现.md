# M0 基线复现

本流程只在新工作区写 `.reference/`、`build/`、`out/` 和中文文档证据，不改原内核源码或原构建目录。需要 Windows x64、Visual Studio 2022 C++ 工具、CMake ≥3.25、Python ≥3.10、Git，以及包含固定对象的原内核/依赖 Git 缓存。缓存缺失时明确失败，不自动使用其他版本。

## 建立参考材料

```powershell
python tools/prepare_baseline.py --repository J:/Code/LaserCNCv3.0 --dependency-cache J:/Code/LaserCNCv3.0/build/vs2022/_deps
python -c "import json,subprocess; subprocess.run(json.load(open('build/donor-configure.json',encoding='utf-8')),check=True)"
cmake --build build/donor-release --config Release --parallel 16
```

每个 Git 依赖从锁定对象导出。Catch2 的锁定值 `95d8a61b...` 是标签对象，解引用后提交为 `8b08d4d...`；二者一并记录。SQLite 下载归档必须匹配规划 donor 的 SHA3-256。已有参考目录内容不符时拒绝覆盖。

## 门禁与初始测量

```powershell
cmake -S . -B build/m0
ctest --test-dir build/m0 -C Release --output-on-failure
ctest --test-dir build/donor-release -C Release --output-on-failure --output-junit ../../docs/evidence/m0/donor-ctest.xml
python tools/run_baseline.py --runs 3 --samples 64
```

VS 是多配置生成器，即使 M0 只有 Python 测试也需要 `-C Release`。门禁初期允许零生产文件会明确打印 M0 状态，M1 出现正式源码后必须移除 `--allow-empty`。

基准包含 gateway、component、journal、lifecycle 七个合法内存/SQLite 组合，均为 1k 对象；三轮独立进程，交替场景顺序。每次执行同时要求退出码 0、唯一完成标记和实际 Release JSON 报告，校验配置及样本数量。报告索引记录源提交、二进制摘要、CMakeCache 摘要、命令和限制。真实数据库和快照只留在忽略的 `out/`，仓库在 `docs/evidence/m0/baseline-时间戳/` 保存原始采样 JSON 与日志；重复执行使用新目录，不覆盖旧失败材料。

## 证据边界

此处只建立当前语义的初始基线。每进程最多 64 次样本不是足量 P99；未运行 1/4/16 客户端、10k/100k 对象、请求规模、任务各阶段延迟、拥塞/慢观察者或新旧 A/B。生命周期测量为每进程 10 个完整创建/验证/停止周期。后续 M3/M8 必须补足适用矩阵，不能用五次均值或此处中位数代替尾延迟预算。

执行器与存储独占等 donor 回归通过，只属于该固定参考构建；新内核要在迁入后重新验证。Debug、ASan 和真正多消费者冻结证据不由此产生。
