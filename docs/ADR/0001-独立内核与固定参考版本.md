# ADR-0001：独立内核与固定参考版本

日期：2026-09-05。状态：采纳。

## 决策

在 `Kernel_v1` 现有 Git 历史上建设新内核。远端初始提交为 `34b24c9b507adf1e12d306649a125d52d6d4eebf`，只含 README。保留用户提供的架构规划原文。原内核工作区只读；不切分支、不重置、不写构建输出。

规划中的 Phase 3 是结构参考，donor 是行为、实现与测试参考。用户本轮进一步明确“原内核实现仅作参考”，因此不把原工程历史或 AppKernel 全量移入新仓库。按单元核对后可复用基础机制，必须登记来源及实际差异。基础层以静态库和可重定位安装包交付，公开命名空间采用 `portable`。

第一正式环境为 Windows x64、C++20、MSVC。Foundation/Contracts/CoreRuntime 不下载第三方依赖。适配器按项选择；未实现组件在配置时明确拒绝，不提供占位成功对象。

状态提供者的基本边界在 M1/M2 确定，但实际 DocumentWorkspace 与 AtomicGroup 执行在 M6 进入。M1 不假造文档或先实现产品模块。M4 只采用同一 Script/Plan AST。

## 证据规则

固定 donor 的 Release 基准只证明该源版本在本机的行为与测量值，不证明新内核正确，也不能替代 M3/M8 的等价语义比较。已有基准最多接受 64 次样本且无完整并发吞吐测量；其输出只报告中位数和原始样本，不升级为 P99。新旧身份语义的差异必须在比较时单列。

M0 可明确记录尚未运行的矩阵，但不能将缺口当作完成。完整执行状态及后续入场条件以唯一执行计划为准。
